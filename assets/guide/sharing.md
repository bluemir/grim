# 다이어그램 공유

grim에서 만든 다이어그램을 다른 사람과 공유하는 방법을 알아봅니다.

## URL 기반 공유 (기본)

grim은 다이어그램 소스 코드를 압축하여 URL의 fragment(`#z=...`)에 저장합니다. 브라우저 주소창의 URL을 그대로 복사하면 누구에게나 공유할 수 있습니다.

- 별도의 서버 저장 없이 URL만으로 다이어그램을 복원할 수 있습니다.
- 소스를 `deflate` 압축 후 base64url로 인코딩하므로, 같은 다이어그램이라도 URL이 훨씬 짧아집니다(복잡한 다이어그램에서 최대 90% 가량).
- fragment(`#`)는 서버로 전송되지 않으며, 다이어그램은 전적으로 URL 안에만 존재합니다.

> **참고**: 예전 형식인 `#data=...` 및 `?data=...`(압축 없는 base64) 링크도 그대로 열립니다. 한 번 편집하면 새 압축 형식(`#z=...`)으로 자동 전환됩니다.

> **GitHub 등에서 링크가 깨질 때**: 일부 서비스는 약 4096자를 넘는 URL을 자동 링크로 처리하지 않습니다. 압축 덕분에 대부분의 다이어그램은 이 한계 안에 들어오지만, 매우 큰 다이어그램이라면 아래 **Short Link**를 사용하세요.

## Short Link (서버 저장)

다이어그램을 서버에 저장하고 `/view/{id}` 형태의 짧은 URL로 공유할 수 있습니다.

### 사용 방법

1. 에디터에서 다이어그램을 작성합니다.
2. 우측 상단의 **"Short Link"** 버튼을 클릭합니다.
3. 현재 내용이 서버에 저장되고, `/view/{id}` URL이 클립보드에 복사됩니다.

### 저장되는 것은 "스냅샷"입니다

- Short Link는 버튼을 누른 **그 순간의 내용**을 저장합니다. 저장된 다이어그램은 바뀌지 않습니다.
- 편집 중인 내용은 서버에 자동 저장되지 않고, 지금처럼 URL(`#z=...`)에만 저장됩니다.
- 내용을 고친 뒤 다시 공유하려면 **Short Link** 버튼을 한 번 더 누르세요. 새 링크가 만들어지고, 예전 링크는 예전 내용을 그대로 보여줍니다.
- 링크 id는 내용으로부터 만들어집니다. 같은 내용으로 다시 누르면 같은 링크가 나옵니다.

### Short Link URL 형식

- **보기**: `/view/{id}` — 읽기 전용으로 다이어그램을 봅니다.
- **편집**: `/edit/{id}` — 저장된 내용을 에디터로 불러옵니다. 불러온 뒤에는 일반 편집과 같이 URL(`#z=...`)에 저장되며, 원래 링크의 내용은 바뀌지 않습니다.

### 보관 기간

- 저장된 다이어그램은 **마지막으로 조회된 뒤 일정 기간**(기본 90일, 서버 설정에 따라 다름)이 지나면 삭제됩니다.
- 누군가 링크를 열어 볼 때마다 기간이 다시 시작되므로, 계속 쓰이는 링크는 사라지지 않습니다.
- `/view/{id}` 화면 상단에 "N일간 조회가 없다면 만료됩니다."와 같이 보관 정책이 표시됩니다.
- 서버 관리자가 특정 다이어그램의 보관 기간을 늘리거나 영구 보관으로 지정할 수 있습니다. (아래 **관리자 명령** 참고)

### 메일 인증으로 보관 기간 늘리기

서버에 메일 발송이 설정되어 있으면 `/view/{id}` 상단에 **메일 인증** 버튼이 나타납니다. 계정이나 가입 없이, 다이어그램마다 메일 주소를 등록합니다.

1. **메일 인증** 버튼을 누르고 메일 주소를 입력한 뒤 **인증 메일 보내기**를 누릅니다.
2. 받은 메일의 **인증하기** 링크를 열고, 열린 페이지에서 버튼을 누르면 인증이 완료됩니다. 링크는 발송 후 24시간 동안 유효합니다.
3. 인증된 다이어그램은 조회 여부와 관계없이 **1년간** 보관됩니다.

- 다이어그램을 볼 수 있는 사람은 누구나 메일을 등록할 수 있고, 한 다이어그램에 여러 메일을 등록할 수 있습니다. 이미 인증된 다이어그램에서는 **메일 추가** 버튼으로 등록합니다.
- 등록된 메일 주소는 화면에 표시되지 않습니다. 등록된 메일 개수만 보입니다.
- 보관 기간이 끝나기 **30일 전**부터 **5일 간격으로 최대 4번**(D-30, D-25, D-20, D-15) 확인 메일을 보냅니다. 여러 다이어그램을 등록했다면 한 통에 모아서 보냅니다.
- 확인 메일의 **연장하기** 링크를 누르면 그때부터 다시 1년간 보관됩니다. 등록된 메일 중 한 명만 응답해도 연장됩니다.
- 끝까지 응답이 없으면 보관 기간이 끝난 뒤 등록된 메일이 모두 지워지고 일반 다이어그램으로 돌아갑니다. 그 시점부터 다시 "N일간 조회가 없다면 만료"가 적용됩니다.
- 더 이상 메일을 받고 싶지 않으면 확인 메일의 **이 다이어그램에서 내 메일 삭제** 링크를 누르세요. 이미 연장된 보관 기간은 유지됩니다.
- 같은 주소로 보내는 인증 메일은 하루 30통으로 제한됩니다.

### 제한

- 다이어그램 소스는 기본 1MiB까지 저장할 수 있습니다. 넘으면 버튼에 **Too Large**가 표시됩니다.
- 같은 IP에서 짧은 시간에 너무 많이 저장하면 잠시 제한됩니다. 기본값은 1시간에 30개로, 한 번에 30개까지 저장할 수 있고 이후에는 2분마다 1개씩 다시 저장할 수 있게 됩니다. 제한되면 버튼에 **Try Later**가 표시됩니다. 이미 저장된 내용을 다시 공유하는 것은 횟수에 포함되지 않습니다.
- IPv6 주소는 `/64` 대역 단위로 묶어서 셉니다.

## 서버 설정

Short Link 기능은 기본적으로 비활성화되어 있습니다. 서버 설정 파일에서 활성화할 수 있습니다.

```hjson
{
    backend: {
        storage: {
            enabled: true
        }
    }
}
```

설정 파일 경로는 서버 실행 시 `-c` 또는 `--config` 옵션으로 지정합니다.

```bash
grim server -c config.hjson --db-path ./grim.db
```

> **참고**: Short Link 기능을 사용하려면 `--db-path` 옵션으로 영구 데이터베이스 경로를 지정해야 합니다. 기본값인 `:memory:`는 서버 재시작 시 데이터가 사라집니다.

### 보관 기간과 제한 설정

```hjson
{
    backend: {
        storage: {
            enabled: true
            // 마지막 조회 후 이 기간이 지나면 삭제. "0"이면 삭제하지 않음
            retention: 90d
            // 저장 가능한 소스 최대 크기
            maxSize: 1MiB
            rateLimit: {
                // IP당 window 동안 새로 저장할 수 있는 개수. 0이면 제한 없음
                create: 30
                window: 1h
            }
        }
    }
}
```

| 항목 | 기본값 | 설명 |
|---|---|---|
| `retention` | `90d` | 마지막 조회 후 보관 기간. `d`(일), `h`, `m` 단위를 쓸 수 있습니다. `"0"`이면 만료되지 않습니다. |
| `maxSize` | `1MiB` | 소스 최대 크기. `KiB`, `MiB` 단위를 쓸 수 있습니다. |
| `rateLimit.create` | `30` | IP당 `window` 동안 새로 저장할 수 있는 개수. 한 번에 모두 쓸 수 있고, 쓴 만큼은 `window` 동안 고르게 다시 채워집니다. `0`이면 제한하지 않습니다. |
| `rateLimit.window` | `1h` | 생성 횟수를 채우는 기간. |

만료된 다이어그램은 서버가 1시간마다 정리합니다.

생성 횟수는 서버 메모리에서 세며, 서버를 재시작하면 초기화됩니다. 메모리가 무한정 늘지 않도록 최대 10만 개의 클라이언트까지만 기억하고, 이를 넘으면 가장 오래전에 요청한 클라이언트의 기록부터 지웁니다.

### 메일 인증 설정

메일 인증은 `backend.mail.smtp.host`를 설정하면 켜집니다. 메일 속 링크를 만들기 위해 서버의 외부 주소(`http.baseURL`)도 함께 지정해야 합니다.

```hjson
{
    http: {
        baseURL: https://grim.example.com
    }
    backend: {
        storage: {
            enabled: true
            retention: 30d
            verification: {
                retention: 365d       // 인증(또는 연장) 후 보관 기간
                remindBefore: 30d     // 만료 몇 일 전부터 확인 메일을 보낼지
                remindInterval: 5d    // 확인 메일 간격
                reminders: 4          // 확인 메일 총 횟수
                linkTTL: 24h          // 인증 링크 유효 시간
                dailyLimit: 30        // 같은 주소로 하루에 보낼 수 있는 인증 메일 수 (0이면 제한 없음)
            }
        }
        mail: {
            smtp: {
                host: smtp.example.com
                port: 587             // 생략 시 starttls 587, tls 465, none 25
                username: grim        // 지정하면 서버가 지원하는 가장 안전한 방식(PLAIN, LOGIN 등)으로 로그인
                password: secret
                from: grim <grim@example.com>
                tls: starttls         // starttls(기본) | tls | none
            }
        }
    }
}
```

`verification` 항목은 모두 생략할 수 있으며, 위 값이 기본값입니다. 메일을 설정하지 않은 서버에서는 메일 인증 버튼이 표시되지 않습니다.

> **참고**: `tls: none`에서는 `localhost`가 아닌 SMTP 서버에 `username`/`password`로 로그인할 수 없습니다. 암호가 평문으로 전송되는 것을 막기 위한 제한입니다.

### 리버스 프록시 뒤에서 실행할 때

생성 횟수 제한은 요청한 클라이언트의 IP를 기준으로 합니다. nginx 같은 리버스 프록시 뒤에서 실행하면 모든 요청이 프록시 IP로 보이므로, 신뢰할 프록시를 지정해 `X-Forwarded-For` 헤더의 IP를 쓰도록 하세요.

```hjson
{
    http: {
        // 이 주소에서 온 요청만 X-Forwarded-For / X-Real-IP 헤더를 믿습니다
        trustedProxies: ["127.0.0.1", "10.0.0.0/8"]
        // 다른 헤더를 쓰는 경우 (예: Cloudflare)
        // remoteIPHeaders: ["CF-Connecting-IP"]
    }
}
```

> **주의**: `trustedProxies`를 지정하지 않으면 헤더를 믿지 않고 접속한 주소를 그대로 씁니다. 모든 주소(`0.0.0.0/0`)를 신뢰하도록 설정하면 누구나 헤더를 위조해 제한을 우회할 수 있습니다.

## 관리자 명령 (`grim storage`)

서버의 데이터베이스 파일을 직접 열어 저장된 다이어그램을 관리합니다. 서버가 실행 중이어도 사용할 수 있습니다.

```bash
# 목록과 만료 예정 시각 보기 (-c 로 서버 설정을 주면 보관 기간을 반영)
grim storage --db-path ./grim.db -c config.hjson ls

# 영구 보관 / 해제
grim storage --db-path ./grim.db pin {id}
grim storage --db-path ./grim.db unpin {id}

# 지금부터 최소 1년간 보관 (조회가 없어도 삭제되지 않음)
grim storage --db-path ./grim.db extend {id} 365d

# 삭제
grim storage --db-path ./grim.db rm {id}
```

`extend`로 늘린 기간, 메일 인증 보관 기간, "마지막 조회 후 보관 기간" 중 가장 늦은 쪽이 적용됩니다. `ls`의 EXPIRES 열에는 `(pinned)`, `(verified)`, `(extended)`로 적용 중인 정책이 표시됩니다.
